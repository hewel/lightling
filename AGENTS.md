# AGENTS.md

Project-specific guidance for AI coding agents.

Astryx v0.4.3 · 156 components
CLI: run every command as `npx astryx <cmd>` (shown below as `astryx ...`).

SETUP (once, in your app entry e.g. main.tsx) — without these, components render unstyled:
  import "@astryxdesign/core/reset.css";
  import "@astryxdesign/core/astryx.css";

WORKFLOW — discover, don't guess. Before writing UI:
1. `astryx build "<idea>"` — START HERE: returns a kit (closest [page] + [block]s + [component]s). No args = full playbook.
2. `astryx template <name> [--skeleton]` — scaffold the [page]/[block]s it named, or study their layout. Templates are reference code.
3. `astryx component <Name>` — props + examples for every component you use.

RULES:
- No <div> — components do all layout/spacing, page frame included.
- Frame first: read `astryx docs layout` before writing any page or screen — page frame, region widths, breakpoint behavior.
- Dense data = rows (Table, List/Item), never Card-wrapped list items; Card is for standalone widgets. Status = StatusDot/Token; Badge = counts only.
- Custom styling: component props first; else StyleX — colocated `stylex.create` in the component file, `xstyle` prop for Astryx components; token values as `'var(--color-*|--spacing-*|--radius-*)'` literals. No raw hex/px.
- Tokens for every value (`astryx docs tokens`). Brand/accent belongs in the theme (`astryx theme list` / `theme add <slug>`, or `astryx theme template` for a custom one) — never override --color-* in :root.
- SELF-CHECK before you finish: re-read the file and replace any raw <div>/<span> layout, imported .css/@apply, or hardcoded value (#hex, 16px) with the component or a token (var(--color-*|--spacing-*|…)). If unsure a component/prop exists, run `astryx component <Name>` / `astryx search "<thing>"`; don't hand-roll CSS.

## Visual validation

- All visual validation is human-only. Agents must not open or drive a browser,
  capture screenshots, or claim visual correctness. For UI changes, complete
  non-visual automated checks and report the affected surfaces and states for
  manual human review.
- Never write tests for styles. Do not assert generated CSS class names,
  computed styles, or pixel geometry; visual and StyleX class output are
  build-dependent and reviewed by humans.

## Extension compatibility boundaries

- `src/themes/astryx-neutral.css` is generated by `npm run prepare:extension`.
  Extension.js drops the package theme's `@scope` blocks, so the provider imports
  this compiler-safe derivative. Never edit it by hand.
- A legacy compatibility adapter may use a small, colocated CSS file only when the
  public Astryx component has no equivalent slot or selector and the rule uses
  design tokens. Keep the exception inside that adapter and cover the behavior.
- A native element is allowed only at browser or Floating UI integration seams
  that require its exact DOM/ref type. Add an infrastructure comment at the seam;
  all ordinary layout still uses Astryx primitives.
